# Neko Wallet

---

ターミナルで動くセルフカストディの暗号化ウォレット。ウォレット全体が
**暗号化されたファイル 1 つ** —— USB メモリで持ち歩き、ネットワークドライブに置き、
どこへでもコピーできます。メールアドレスとパスワードで解錠しますが、
その 2 つはどこにも保存されていません。

マルチチェーン設計：TRON、Ethereum、BNB Chain、Polygon、Base、Arbitrum、Optimism、Avalanche、HyperEVM、Mantle、Linea、zkSync Era、Scroll、Aptos、Sui、Solana、Bitcoin、TON。

## これは何か

ターミナルで動く暗号資産ウォレットです。鍵はローカルの暗号化された SQLite 金庫に
入っています。ログインするアカウントはなく、何かを預かるサーバーもなく、同期もしません。
このプログラムが接続するのは**あなたが指定したチェーンのノード**と、
——あなた自身がキーを入力した場合に限り——BNB Chain の履歴用インデクサだけです。
更新確認もテレメトリも解析もなく、**価格サービスもありません**。ウォレット一覧の
評価額は、すでに接続しているチェーン上のスワッププールから直接引いた値なので、
表示にプライバシー上の代償がありません。ドルではなく USDT 建てで、その旨を明記します
——実際に問い合わせたのはそちらだからです。

ストレージのスキーマから上まで **ウォレット → チェーン → 資産** として作られています。
今動くのは TRON です。[対応チェーン](#対応チェーン)を参照してください。

金庫は**自己完結したファイル 1 つ**です。USB メモリにコピーして、あとで戻せば、
すべてそこにあります。ファイルを持ち去った人が手にするのは暗号文だけです。

```
$ neko-wallet
メールアドレス: zoe@example.com
パスワード:

  ⠸ 鍵を導出中... ここが遅いのは意図的です

┌──────────────────────── ウォレット ────────────────────────┐
│ > 貯蓄            TPZrDZ...  8.655007 TRX  7.00 USDT        │
│   日常            TWx3kQ...  0.000000 TRX  0.00 USDT        │
└─────────────────────────────────────────────────────────────┘
 n 新規   i インポート   Enter 開く   s 設定   q 終了
```

> [!WARNING]
> **復旧の手段はありません。** マスターフレーズも、リセットリンクも、サポートもありません。
> メールアドレスかパスワードを忘れた時点でウォレットは失われます ——
> ファイルを盗んだ人とまったく同じ立場になります。これは欠陥ではなく設計です。
> `.db` のコピーを保管してください —— 暗号化されているので、コピーは安価かつ安全です。
> リカバリーフレーズを紙に書き写すことを考える前に、[バックアップ](#バックアップ)を
> 読んでください。あれは響きほど無害な作業ではありません。

## インストール

**macOS、Linux、WSL:**

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

**Windows PowerShell:**

```powershell
irm https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.ps1 | iex
```

**Windows CMD:**

```
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.cmd -o install.cmd && install.cmd
```

インストーラはあなたの環境向けのリリースをダウンロードし、公開されたチェックサムと
照合し、PATH に配置して終了します。ウォレットは作らず、何も尋ねません。

スクリプトをシェルにパイプするということは、その URL が返すものを何であれ実行する
ということです。気になる方は先に読んでください —— [install.sh](install.sh) は
200 行ほどです。`NEKO_WALLET_INSTALL_DIR` で配置先を変更でき、
`NEKO_WALLET_NO_PATH=1` を指定するとシェルの起動ファイルに手を触れません。

### ソースからビルド

```bash
cargo install --git https://github.com/zoefix/neko-wallet
```

実行ファイル 1 つ、実行時依存なし —— SQLCipher は組み込みでコンパイルされます。
Windows でソースからビルドする場合は Perl と NASM が必要です。あちらでは OpenSSL を
ソースからビルドするためです。

## 使い始める

```bash
neko-wallet
```

初回起動でメールアドレスとパスワードを設定し、金庫を作成します。そのあとは:

| キー | 動作 |
|---|---|
| `n` | 新しいウォレット（リカバリーフレーズを生成しますが**表示しません**） |
| `i` | リカバリーフレーズまたは秘密鍵からインポート |
| `Enter` | 開く → チェーン → 資産 |
| `y` | アドレスをコピー |
| `s` | 送金 |
| `t` | 取引履歴 |
| `m` | このウォレットのリカバリーフレーズを表示 |
| `<` `>` | 言語を切り替え |
| `L` | 今すぐロック |

新規作成時にフレーズは表示されません。あとから `m` で意図的に呼び出す形で、
そのときにパスワードをもう一度尋ねます。

## 対応チェーン

ウォレットが持つ 1 つのリカバリーフレーズが、その下のすべてのチェーンを覆います ——
BIP44 の導出パスはそのためのものです。チェーンを増やすことは、新しいウォレットも、
新しいフレーズも、バックアップ対象が増えることも意味しません。

| チェーン | 状態 | 資産 |
|---|---|---|
| TRON | 動作 | TRX、USDT (TRC20) |
| BNB Chain | 動作 | BNB、USDT (BEP20) |
| Solana | 動作 | SOL、USDT (SPL) |
| Bitcoin | 動作 | BTC |
| Ethereum | 動作 | ETH、USDT (ERC20) |
| Polygon | 動作 | POL、USDT (ERC20) |
| Base | 動作 | ETH、USDC (ERC20) |
| Arbitrum | 動作 | ETH、USDT (ERC20) |
| Optimism | 動作 | ETH、USDT (ERC20) |
| Avalanche | 動作 | AVAX、USDT (ERC20) |
| HyperEVM | 動作 | HYPE、USDT (ERC20) |
| Mantle | 動作 | MNT、USDC (ERC20) |
| Linea | 動作 | ETH、USDC (ERC20) |
| zkSync Era | 動作 | ETH、USDC (ERC20) |
| Scroll | 動作 | ETH、USDT (ERC20) |
| Aptos | 動作 | APT、USDT (fungible asset) |
| Sui | 動作 | SUI、USDC (coin objects) |
| TON | 動作 | GRAM、USDT (jetton) |

Polygon も同じコインタイプを使うため、同じフレーズは 3 つの EVM チェーンで
**同じアドレス**になります。固有の点が 2 つあります。コインは **POL** で、2024 年 9 月に
MATIC から改称されました。それはチェーン自身が示しており、このウォレットの判断根拠でも
あります。ラップされたネイティブトークンのコントラクトが `WPOL` と答えるからです。
USDT のコントラクトは **`USDT0`** と名乗ります。Tether が Polygon 上の供給をオムニ
チェーン版へ移したためです。これは誰もが USDT と呼んでいるものそのもので、ウォレットも
USDT として表示します。署名前にチェーンと照合するのは、コントラクトが実際に名乗る名前
です。Polygon の履歴は NodeReal ではなく **Blockscout** から取得します。NodeReal が
このチェーンを索引していないためです。キーは不要なので、ここで唯一、頼まれずとも
接続する索引でもあります。Bitcoin が Esplora と結んでいるのと同じ取り引きで、理由も
同じです。`eth_getLogs` は 1 万ブロックが上限で、1.5 秒ブロックのこのチェーンでは
4 時間分にしかならず、そもそもネイティブ送金はログを出しません。

設定の **Etherscan API キー**は任意で、1 つでここの EVM チェーンすべてをまかないます。
設定されていれば他より優先されます。

Base は 4 つ目の EVM チェーンで、アドレスはやはり同じです。コインは ETH ——
Ethereum と同じ資産で、両チェーンの送金を分けるのはチェーン ID だけです。できないのは
そのコインの値付けです。Base 自身の Uniswap V2 WETH/USDT ペアは存在しますが、
**合計で 17 ドルほど**しかなく、1 ETH の価値を尋ねると 17 という答えが返ります。
Base の流動性は Aerodrome と Uniswap V3 にあり、どちらも同じインターフェースでは
ないため、価格は Ethereum のプールから読みます。同じ資産で、しかも既に通信している
チェーンです。BTC と同じ取り引きです。履歴は Polygon と同様 Blockscout から取得します。

もう 1 つ、Base が Optimism とだけ共有する事情があります。**手数料はガス×単価では
ありません。** OP-stack ロールアップは取引を Ethereum に書き込み、その費用を L2 ガスとは
別に送金者へ請求します。しかも `op-geth` はそれを残高チェックに含めます。手数料をガス×
単価とみなすウォレットはちょうどその分だけ足りず、「全額送金」は `have … want …` で
拒否されます。この金額は実際に署名するバイト列をチェーン上の L1 ガス価格オラクルに渡して
取得し、確認画面に独立した行として表示します。返金はされません。

課金対象は**圧縮後**のサイズです。したがって、まだ存在しない署名の代わりに何のバイトを
置くかは細部ではなく金額そのものになります。同じ値が続く詰め物は圧縮で消えてしまい、
確保額が不足します。両チェーンのオラクルで実測したところ、その不足はチェーンと
トークン送金かどうかにより 1.33 億から 6.33 億 wei でした。

Base はここで唯一、ステーブルコインが **USDT ではなく USDC** のチェーンでもあります。
好みの問題ではありません。Tether の Base 上の残高は約 2,380 万で、Circle の USDC は
42 億です。さらに Binance が USDT の出金先として挙げる 19 のネットワークに Base は
含まれておらず、そこでは ETH と USDC のみを扱っています。USDT の行を置いても、誰も
埋められない行になります。そのためチェーンごとのトークン枠は「そのチェーンの
ステーブルコイン」であり、それがどれなのかをウォレットが示します。

Arbitrum One は 5 つ目の EVM チェーンで 2 つ目のロールアップですが、L1 の課金方法が
逆です。Nitro は Ethereum への書き込み費用をガスの**見積もり**に織り込みます。
通常の送金の見積もりが 21,000 ではなく 21,302 になるのはそのためで、
`gas_limit × 単価` に既に含まれており、別途確保するものはありません。Base には
その確保が必要で、こちらにあってはいけません。ここで架空の L1 手数料を引けば、
「全額送金」のたびに端数が残ります。コインは ETH で、価格は Base と同じ理由で
Ethereum から読みます。自前のプールは約 3 万ドルしかなく、14% 遅れているからです。
USDT は本物で 8.35 億あり、Binance からも送れますが、コントラクトは `USD₮0` と
名乗ります。T の位置にトゥグルグ記号が入っています。この名前は照合にのみ使い、
表示はしません。

Optimism は 6 つ目の EVM チェーンで 3 つ目のロールアップであり、「ロールアップかどうか」
という問いが役に立たなくなる場所です。Base と同じ OP-stack なので L1 手数料を別に確保し
オラクルに問い合わせます。Arbitrum も同じくロールアップですが、問い合わせてはいけません。
どちらなのかはチェーンが答えます。通常の送金の見積もりは 2 つの OP-stack チェーンでは
ちょうど 21,000 ガス、Arbitrum では 21,422 ガスで、その差が既に織り込まれた書き込み費用です。

隣のチェーンから写すと間違えるものが 2 つあります。Uniswap V2 のルーターアドレスが
Base・Arbitrum と**異なります**。あの 2 つは同じアドレスを共有していますが、それは
Optimism にはコードがありません。写してもエラーにはならず、ただ何も返らず、価格が
静かに消えます。もう 1 つ、Polygon の `USDT0` や Arbitrum の `USD₮0` と違い、ここの
USDT コントラクトは素直に `USDT` と名乗ります。2.235 億あり、アドレスは Binance が
出金先として挙げるものと一致します。コインは ETH で、価格は Ethereum から読みます。
自前の V2 プールはそれぞれ 15 ドルと 592 ドルしかなく、ETH を 7.55 ドルと 264 ドルと
答えるからです。履歴は Blockscout から取得しますが、こちらは独自ドメインで動いています。
NodeReal はこのチェーンの RPC を提供していますが索引はないため、履歴には使いません。

このバッチで 6 チェーンをまとめて追加しました。分類の基準は名前ではなく、L1 の
費用をどう請求するかです。

| チェーン | コイン | ステーブル | L1 手数料 | 価格の取得元 |
|---|---|---|---|---|
| Avalanche | AVAX | USDT（`USDt`） | — | 自前のプール |
| HyperEVM | HYPE | USDT（`USD₮0`） | — | **なし** |
| Mantle | MNT | USDC | ガスとは別 | **なし** |
| Linea | ETH | USDC | — | Ethereum |
| zkSync Era | ETH | USDC | ガスに含む | Ethereum |
| Scroll | ETH | USDT | 別、しかも**独自アドレス** | Ethereum |

**Scroll は L1 を独自のアドレスで請求します。** `L1GasPriceOracle` は `0x53..02`
にあり 3,782 バイト。Base・Optimism・Mantle が共有する OP-stack のプリデプロイは
`0x42..0F` で 2,055 バイトです。どちらも同じ `getL1Fee(bytes)` に応答するため
設定は 1 つで足りますが、Scroll のものを OP-stack のアドレスに探しに行くとコードは
無く、確保額はゼロになります。

**zkSync Era は通常の送金を約 178,000 ガスと見積もります。** 21,000 ではありません。
Ethereum への公開費用をガスの数値に織り込むためで、Arbitrum と同じ方式をさらに
推し進めたものです。別途確保するものはありません。この数値を 21,000 に「直す」
ウォレットは、ブロックに入れられない取引を作ります。

**2 つのチェーンには意図的に価格を出しません。** HYPE と MNT はこのウォレットが
話す他のどのチェーンにも存在せず、自前の Uniswap V2 プールは約 1,100 ドルと
400 ドルしかありません。その規模のプールは失敗せず、数値を返します。HyperEVM の
スポット価格は 0.1% 以内で正しいのに、1 コインの見積もりは 13% 低く出ます。1 単位が
プールの 6 分の 1 だからです。ですから評価額の列は「分からない」と言います。これは
真実であり、見た目では分からない誤差を含む数値より優れています。

**Avalanche と Mantle の履歴は Routescan から取得します。** Snowtrace を運営している
ところで、キーは不要です。ここで扱うチェーンのうち対応しているのはこの 2 つだけで、
他の 10 には `chain not supported` を返します。そしてこの 2 つにとっては唯一の
インデックスです。NodeReal はどちらも扱わず、Blockscout インスタンスもありません。
履歴に自分の Etherscan キーが要るチェーンは HyperEVM と Linea だけになり、その 2 つは
失敗を装わずそう表示します。

**そして同じ 3 文字が 4 通りに綴られます。** Tether のコントラクトは Ethereum と
Scroll では `USDT`、Polygon では `USDT0`、Arbitrum と HyperEVM ではトゥグルグ記号の
`USD₮0`、Avalanche では小文字の t で `USDt` と名乗ります。いずれも署名前にチェーンと
照合され、いずれも画面には表示されません。

ここには EVM ではなく、互いにも似ていないチェーンが 2 つあります。

**Aptos** はコインと**ファンジブルアセット**を別の仕組みとして持ち、USDT は後者です。
エントリ関数も残高の読み方も異なり、一方を他方に対して使っても金額が狂うのではなく
取引が中断します。アドレスは `sha3_256(公開鍵 || スキーム)` なので、同じ鍵でも
スキームが違えば別のアカウントです。

取引のエンコードは文書ではなくチェーン自身のエンコーダと突き合わせました。Aptos は
`/transactions/encode_submission` で取引を BCS 化して返します。このウォレットの
バイト列はそれと**完全に一致**しました（2 種類の送金でそれぞれ 197 と 297 バイト）。
BCS は型を持たないため、長さバイトを 1 つ間違えても壊れた取引にはならず、
別の取引が正しく署名されるだけだからです。

手数料は見積もりではなく**上限**として表示します。Aptos は正確に価格を出せますが、
送信者の公開鍵を示した場合に限られます。見積もり時点のウォレットはそれを持ちません。
鍵は最後の段階で導出され、公開鍵はそのハッシュであるアドレスから復元できないためです。
使わなかったガスは請求されません。

**Sui には数値の入った口座がありません。** コインは**オブジェクト**で、それぞれに id、
バージョン、ダイジェストがあります。残高はその合計であり、送金は特定のオブジェクトを
使います。Bitcoin に次いで、送るという操作が引き算ではなく選択になる 2 つ目のチェーンで、
バージョンが古いことは「少なく送る」ではなく「拒否」を意味します。「送金」という命令も
ありません。すべての取引はコマンドの並びで、支払いは分割してから引き渡すことです。

アドレスは `blake2b256(スキーム || 公開鍵)` です。順序に注意してください。Aptos とは
逆です。2 つのチェーン、2 つの Ed25519 鍵、2 つの 32 バイトアドレス。オペランドを
入れ替えると、もっともらしく見えて誰も鍵を持たないアカウントになります。メインネットの
実際の取引から署名者の公開鍵を読み出し、アドレスを再計算して確認しました。

手数料はその取引そのものの dry run から得ます。これはバイト列が正しいことの証明でも
あります。価格を出すにはチェーン自身のパーサがそれを読む必要があるからです。知って
おく価値のある帰結が 1 つあります。Sui は請求したストレージの一部を払い戻し、コイン
オブジェクトの統合はストレージを解放するため、30 個をまとめる送金は**まったく費用が
かからない**ことがあります。

注意点が 1 つ。Sui 自身の公開フルノードは JSON-RPC を**廃止**し、すべてに
"Method not found" を返します。ここでの既定ノードは、まだそれを提供する別のノードです。

TON はここで唯一、**アドレスが鍵から導出されない**チェーンです。TON のウォレットは
スマートコントラクトそのものであり、アドレスはそのコントラクトの初期コードとストレージの
ハッシュです。そこから来る二つのことは隠さず画面に出しています。ウォレットからの最初の
送金はコントラクトのコードを一緒に運びます —— それまでそのアドレスは残高を持つだけで、
動かせるものが何もないからです。そして USDT を送るには GRAM が要ります。トークン送金は
二つのコントラクト間のメッセージで、各ホップはメッセージに同送されたコインで動くからです —— その大半は戻ってきます。送金画面はこの同送額を手数料とは別に表示し、
足し合わせません。

アドレスがウォレットコントラクトに依存するため、**同じフレーズでも、ここでの TON
アドレスは Tonkeeper や Telegram のものと一致するとは限りません** —— 相手も v4R2 と
標準の subwallet id を使っている場合を除きます。よくある既定値ですが、保証ではありません。
コインの名前は GRAM です。2026 年 6 月 15 日に Toncoin から、Telegram の 2018 年
ホワイトペーパーで使われていた名前に戻りました。変わったのはティッカーだけで、
ネットワークは今も TON、アドレスと残高はそのままです。

チェーン固有のコードは 1 つのクレートに閉じ込めてあります。鍵導出・保存・暗号化・
インターフェースは共通でチェーン非依存であり、データベースは最初のマイグレーションから
SLIP-44 のコインタイプを持つ `chains` テーブルを備えています。
本 README のエネルギー・帯域・手数料見積もりの節は TRON 固有です。
それ以外はどのチェーンにも当てはまります。

## ウォレットはファイルそのもの

バックアップと機種変更のすべてがここに懸かっているので、この節は理解する価値があります。

```
neko-wallet.db     ← これがウォレットです。すべて。
```

ファイル 1 つ。`-wal` も `-shm` も付随する状態ファイルもありません ——
データベースが `journal_mode = DELETE` で動いているのはまさにこのためで、
このファイルをコピーすればすべてをコピーしたことになります。全体が暗号化されているので、
鍵なら絶対に置かないような場所にも置けます:

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/            # USB メモリ
cp ~/.local/bin/neko-wallet.db ~/Dropbox/backup/        # クラウドストレージ
```

別の場所にある金庫を使うには:

```bash
neko-wallet set db /Volumes/USB/neko-wallet.db   # 以後これを記憶
neko-wallet --db /Volumes/USB/neko-wallet.db     # 今回だけ
neko-wallet --where-db                           # 今どれを開くのか
neko-wallet unset db                             # 既定の探索に戻す
```

`set db` にメールアドレスもパスワードも不要です。パスを記録するだけで、
それ以外は何もしません。存在しないパスは `--new` を付けない限り拒否します ——
パスが存在しない理由はたいてい打ち間違いであり、その結果は
「ウォレットが消えた」ように見える初回設定画面だからです。

どのファイルを開くかの順序: `--db` → `$NEKO_WALLET_DB` → 保存された設定 →
実行ファイルと同じディレクトリ → OS のデータディレクトリ。

## バックアップ

バックアップは 2 種類あり、**壊れ方が正反対**です。必要になる前に、
どちらがどちらなのか知っておく価値があります。

### `.db` ファイル —— 頼るべきはこちら

全体が暗号化されています。USB メモリやクラウドに置いたコピーは暗号文であり、
拾った人にはやはりメールアドレスとパスワードが必要です。ですから遠慮なく、
何度でもコピーしてください。

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/
```

これで防げないのは**パスワードを忘れること**です。その時点で、このファイルは
あなたにとっても泥棒にとっても同じだけ無価値になります。

### リカバリーフレーズ —— 最後の手段であって、日常のバックアップではありません

> [!CAUTION]
> **12 語を紙に書き写すことを、主たるバックアップとして推奨しません。**
> 紙のフレーズは**平文の持参人証券**です。読んだ人は誰でも、その場であなたの資金を
> 動かせます —— 侵入した泥棒、家に来た客、肩越しに撮られた 1 枚の写真、
> あるいは単にあなたから奪い取った誰か。パスワードは要求されず、警告も出ません。
> `.db` ファイルにはその性質が一切なく、だからこそ頼るべきバックアップなのです。

それでも書き写すのであれば、その紙はウォレットの中の金額そのものと同じ価値を持ち、
同じように保管されるべきです。

- 金庫か銀行の貸金庫へ。引き出しでも、ノートでも、本の間でもありません。
- 写真、クラウドメモ、自分宛てのメッセージ、機器への入力は**絶対に避けてください**。
  同期するものは、その時点であなたの管理下を離れています。
- 金額に見合うなら 2 か所に分けて保管し、1 回の侵入では足りないようにします。

盗まれたフレーズ単体を無価値にできる唯一の仕組みが BIP39 パスフレーズ ——
頭の中だけにある「25 番目の単語」です。neko-wallet はウォレットを**インポート**する
ときにこれを受け付けますが、新規生成時に設定する導線はまだありません。

## 送金

確認はキーを 1 つ押すことではありません。**送金先アドレスの末尾 6 文字を自分で入力**します。

```
   送金先  TPZrDZ TUWQqqUTVRxAmSdQyGXSSg AUyyk4
           ^^^^^^                        ^^^^^^

   確認のため末尾 6 文字を入力してください:
           [ AUyyk_ ]  5/6
```

貼り付けの瞬間にアドレスを差し替えるクリップボード乗っ取りマルウェアは、
コマンドラインウォレットにおける実際の資金喪失の最大の原因です。`y` を押しても
それは防げません —— あなたが見ているのは、自分が貼り付けた**と思っている**ものだからです。
末尾を打ち直すことだけが、これから署名されるバイト列に目を向けさせる唯一の動作です。

そのあとパスワードをもう一度、完全に入力します。持ち主が離席した解錠済みの端末が、
そのまま送金できてしまってはいけません。

**手数料は内訳付きで表示されます。** TRON に一律の手数料はないからです。送金は帯域を、
コントラクト呼び出しはエネルギーを消費し、アカウントで賄えない分だけ TRX が焼かれます。
エネルギーは推測ではなく、その送金そのものをチェーン上でシミュレートして求めます ——
同じ USDT 送金でも、USDT を一度も保有したことのないアドレス宛ては約 2 倍かかります。

### アドレスポイズニング

攻撃者は、あなたが使っているアドレスによく似たアドレスからダストを送りつけ、
履歴から間違ったほうをコピーするのを待ちます。3 つの防御:

- ダストは既定で非表示。
- **アドレスを省略表示することは一切ありません。** `TPZr…yyk4` のように描画した時点で、
  偽物と本物は見分けがつかなくなります。
- 送金先が履歴のどれかに**似ているが一致しない**場合、はっきり警告します。

## リカバリーフレーズ

`m` でウォレットの 12 語を表示します。その前に:

- 金庫がすでに開いていても、Argon2id を含めてパスワードを**完全に再導出**します。
- 語は伏せられており、矢印キーで**一度に 1 語ずつ**だけ開きます。スクリーンショットや
  `tmux capture-pane` で漏れるのは 12 分の 1 であって、全部ではありません。
- 60 秒後に自動で隠れます。
- **コピーは「拒否される」のではなく、存在しません。** その画面からどのクリップボード
  実装へも経路がないので、将来のバグが判定を反転させて有効化することもありません。

画面には、これらが防げないことも書いてあります: カメラ、背後の人、`script`、
画面録画ソフト、そしてすでにその機械にいるマルウェア。ターミナルが画面上の秘密を
守れると主張するウォレットは、嘘をついています。

語を紙に書き写す前に[バックアップ](#バックアップ)を読んでください ——
書き写したフレーズは持参人証券であり、より安全なバックアップは `.db` ファイルです。

## 言語

English、简体中文、繁體中文、日本語。システム設定から自動判定し、設定画面の
`<` `>` でいつでも切り替えられ、金庫ごとに記憶されます。

どの言語もそれ自身の文字で一覧に出るので、今の言語が読めない人でも戻ってこられます。
翻訳はコンパイル時に検査されます: キーの欠落、`%{プレースホルダー}` の不一致、
曖昧幅の文字は、資金を持つ利用者に届く前にビルドを失敗させます。

## しくみ

### 鍵の階層

```
メール+パスワード ─Argon2id─► stretched ─HKDF─┬─► ファイル鍵 ──► SQLCipher（DB 全体）
                                              └─► KEK ──► MK を開封（32 バイトの乱数）
                                                           │
                                                      HKDF ├─► k_data   フィールド単位 AEAD
                                                           └─► k_index  ブラインドインデックス
```

各ウォレットは独立した BIP39 フレーズを持ち、`k_data` で暗号化して保存されます。
`MK` は純粋な乱数でどのフレーズとも無関係です —— だからこそ**マスターフレーズは
存在しません**。パスワード変更はその 32 バイトを包み直すだけで、他のデータを
再暗号化しません。しかもクラッシュ安全です（切り替え完了まで両方の包みを保持します）。

### 二重の暗号化

ファイル全体が SQLCipher で暗号化されます（AES-256-CBC + HMAC-SHA512）。
その上で、漏れれば資金の喪失に直結するものには、別鍵の
XChaCha20-Poly1305 の封筒がもう一枚かかります:

| フィールド | 第 2 層 |
|---|---|
| リカバリーフレーズのエントロピー | あり |
| 秘密鍵 | あり |
| ウォレット名 | あり —— 「会社の予備資金」という名前自体が情報です |
| TronGrid API キー | あり |
| アドレス・取引・残高 | なし —— チェーン上で公開されており、索引と並べ替えが要ります |

各暗号文の AAD はテーブル名・列名・行 ID・鍵バージョンに束縛されているので、
行同士を入れ替えても復号できません。

### ソルトをどこに置くか

自己完結したファイルはそれ自身だけで復号できねばなりませんが、復号するには
**先にソルトが要ります**。SQLCipher は 16 バイトのソルトをファイル先頭に平文で
置いています —— そこで、その領域を自前のヘッダーとして使います:
フォーマット版、KDF プロファイル、そしてこの金庫に固有の 14 バイトの乱数です。

プロファイルを認証されないヘッダーに置くのは安全です。書き換えれば違う鍵が導出され、
ファイルはそもそも開きません。ダウングレード攻撃は自分で自分を無効化します。

### 計算コスト

Argon2id を、セットアップ時にあなたの機械で実測して較正します ——
128 MiB / t=4、256 MiB / t=3、または 1 GiB / t=4。プロファイル番号はヘッダーに
入るので、速い機械で作った金庫は遅い機械でもそのまま開きます。

パスワードは推定エントロピー 70 bit を超える必要があります。文字種による推定と
パターンによる推定の**小さいほう**を採るので、`MyWallet2026!` は実態どおりに
採点されます。

### 取引はローカルで組み立てる

`/wallet/createtransaction` は決して呼びません。ノードが提供するのはブロック参照だけで、
署名対象のバイト列は手書きの protobuf エンコーダでこちらが組み立てます。署名後は
ただちに署名から公開鍵を復元し、アドレスの一致を確認します。悪意あるノードが、
自分宛ての送金を渡して署名させることはできません。

## アップグレード

インストーラをもう一度実行してください。

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

実行ファイルを置き換えるだけで、`.db` には決して触れません ——
終了時にその旨を明示します。

**自己更新は意図的に持ちません。** 自分の実行ファイルを置き換えられるウォレットとは、
鍵を保持している機械へのリモートコード経路を持つウォレットのことであり、
どれだけ署名検証を重ねてもその経路は「そもそも無い」より小さくはなりません。
CI がこれを強制します: 自己置換系のクレートが依存ツリーに戻るか、
許可リストにない通信先が増えると、ビルドが失敗します。
許可リストは手で書き換えないと広がりません。現在あるのは三つのチェーンのノード、
任意の BNB Chain 履歴インデクサ、そしてエクスプローラのリンク
（コピーするだけで、ウォレット自身は取得しません）だけです。

## 何を守り、何を守らないか

**守るもの:**

- `.db` ファイルのコピー、クラウド同期からの流出、廃棄したディスクからの復元 ——
  パスワードがなければ暗号文にすぎません。
- その暗号文の行単位・列単位の改竄。
- KDF のコストパラメータを弱めて解読しやすくする改竄。
- 悪意ある、あるいは乗っ取られたノードによる、他人宛て送金への署名の誘導。

**守らないもの:**

- **パスワードを忘れること。** 永久かつ完全な喪失です。「復旧なし」とはこの意味です。
- 実行している機械のキーロガーやリモートアクセス型トロイの木馬。
  **これはハードウェアウォレットではありません**: 金庫が開いている間、鍵はこの
  コンピュータのメモリ上にあり、ターミナルプログラムにそれは変えられません。
- 解錠中プロセスのメモリダンプ。鍵はゼロ化し、可能な限り `String` に置かないように
  していますが、OS のレイヤーには勝てません。
- 画面からリカバリーフレーズを読み取られること。
- 弱いパスワード。`Password123` は Argon2id を通しても `Password123` のままです。

## 開発

```bash
cargo test --workspace                              # 275 個のテスト
cargo clippy --workspace --all-targets -- -D warnings
```

暗号処理・鍵導出・TRON の取引エンコードは `vectors/` にある凍結された言語横断の
テストベクタと照合されます —— バイト単位で厳密なので、導出されるアドレスや
取引 ID を変えてしまう変更は即座に失敗します。

```
neko-crypto   Argon2id / XChaCha20-Poly1305 / HKDF。IO なし、SQL なし、async なし
neko-vault    鍵の階層、KDF プロファイル、パスワード方針、正規化
neko-store    SQLCipher、マイグレーション、フィールド単位の封筒（鍵は導出しない）
neko-hd       BIP39 / BIP32 / BIP44 と SLIP-0010、TRON / EVM / Solana アドレス
neko-tron     TRON 専用: protobuf、取引の組み立てと署名、ノードクライアント
neko-evm      5 つの EVM チェーン: RLP、EIP-155/1559 署名、ABI、JSON-RPC、ロールアップ手数料
neko-solana   Solana: Ed25519、取引エンコード、トークン口座、クラスタ RPC
neko-btc      Bitcoin: bech32、segwit v0 署名、コイン選択、Esplora
neko-ton      TON: cell と BoC、ウォレット v4R2、jetton、toncenter
neko-core     UI が話す唯一のファサード
neko-i18n     コンパイル時に検査される翻訳テーブル
neko-tui      ratatui のインターフェース
```
