# Neko Wallet

---

一個跑在終端機裡的自託管加密錢包。整個錢包就是**一個加密檔案** ——
插隨身碟帶走、放雲端硬碟、隨便拷到哪裡都行。用一個信箱加一個密碼解鎖，
而這兩樣東西哪裡都沒有儲存。

多鏈架構：TRON、Ethereum、BNB Chain、Polygon、Base、Arbitrum、Optimism、Avalanche、HyperEVM、Mantle、Linea、zkSync Era、Scroll、Aptos、Sui、Solana、Bitcoin、TON。

## 這東西是做什麼的

一個在終端機裡執行的加密貨幣錢包。私鑰存在本機加密的 SQLite 金庫裡；沒有帳號要登入，
沒有伺服器保存任何東西，也不做同步。程式會聯繫的只有**你自己指定的鏈節點**，
以及 —— 僅當你自己填了 Key 時 —— 一個用於 BNB Chain 歷史的索引服務。
不檢查更新、不回報資料、沒有任何統計，**也沒有行情服務**：錢包列表裡那個估值
是從鏈上的兌換池直接問出來的，所以顯示它不花費任何隱私。它以 USDT 計價而不是美元，
並且介面上如實標註 —— 因為那才是實際問到的東西。

從儲存結構往上就是照著**錢包 → 鏈 → 資產**設計的。目前能用的是 TRON，
見[支援的鏈](#支援的鏈)。

金庫是**一個自我包含的檔案**。拷到隨身碟上，回頭再放回來，東西全在。
別人把這個檔案拿走，拿到的是一堆密文。

```
$ neko-wallet
信箱: zoe@example.com
密碼:

  ⠸ 正在推導金鑰... 這裡慢是故意的

┌──────────────────────── 錢包 ────────────────────────┐
│ > 儲蓄            TPZrDZ...  8.655007 TRX  7.00 USDT  │
│   日常            TWx3kQ...  0.000000 TRX  0.00 USDT  │
└───────────────────────────────────────────────────────┘
 n 新增   i 匯入   Enter 開啟   s 設定   q 離開
```

> [!WARNING]
> **沒有任何找回途徑。** 沒有主助記詞、沒有重設連結、沒有客服。
> 忘了信箱或密碼，錢包就沒了 —— 你的處境和拿走檔案的小偷完全一樣。
> 這是設計，不是缺陷。請給 `.db` 留一份副本 —— 它是加密的，所以複製既便宜又安全。
> 在你考慮把助記詞抄在紙上之前，請先讀[備份](#備份)：那一步沒有聽起來那麼無害。

## 安裝

**macOS、Linux、WSL：**

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

**Windows PowerShell：**

```powershell
irm https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.ps1 | iex
```

**Windows CMD：**

```
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.cmd -o install.cmd && install.cmd
```

安裝腳本下載適合你機器的版本，對照公布的校驗碼驗證，放進 PATH，然後就結束了。
它不建立錢包，也不跟你要任何東西。

把腳本管線給 shell 意味著執行那個 URL 提供的任何東西，介意的話請先讀一遍 ——
[install.sh](install.sh) 大約兩百行。`NEKO_WALLET_INSTALL_DIR` 改安裝位置，
`NEKO_WALLET_NO_PATH=1` 則不動你的 shell 啟動檔。

### 從原始碼編譯

```bash
cargo install --git https://github.com/zoefix/neko-wallet
```

單一執行檔，沒有執行期相依 —— SQLCipher 是編譯進去的。Windows 上從原始碼編譯需要
Perl 和 NASM，因為那邊的 OpenSSL 要從原始碼建置。

## 上手

```bash
neko-wallet
```

首次執行會讓你設定信箱和密碼，並建立金庫。然後：

| 按鍵 | 作用 |
|---|---|
| `n` | 新增錢包（產生助記詞，但**不顯示**） |
| `i` | 從助記詞或私鑰匯入 |
| `Enter` | 開啟 → 鏈 → 資產 |
| `y` | 複製地址 |
| `s` | 轉帳 |
| `t` | 交易紀錄 |
| `m` | 檢視這個錢包的助記詞 |
| `<` `>` | 切換語言 |
| `L` | 立即鎖定 |

新增錢包時不會給你看助記詞。你要在之後主動按 `m` 去看 —— 而那會再問一次密碼。

## 支援的鏈

一個錢包的那一份助記詞，涵蓋它底下的所有鏈 —— BIP44 推導路徑就是做這個用的。
加一條鏈，永遠不代表新錢包、新助記詞、或者多一樣要備份的東西。

| 鏈 | 狀態 | 資產 |
|---|---|---|
| TRON | 可用 | TRX、USDT (TRC20) |
| BNB Chain | 可用 | BNB、USDT (BEP20) |
| Solana | 可用 | SOL、USDT (SPL) |
| Bitcoin | 可用 | BTC |
| Ethereum | 可用 | ETH、USDT (ERC20) |
| Polygon | 可用 | POL、USDT (ERC20) |
| Base | 可用 | ETH、USDC (ERC20) |
| Arbitrum | 可用 | ETH、USDT (ERC20) |
| Optimism | 可用 | ETH、USDT (ERC20) |
| Avalanche (AVAX C-Chain) | 可用 | AVAX、USDT (ERC20) |
| HyperEVM | 可用 | HYPE、USDT (ERC20) |
| Mantle | 可用 | MNT、USDC (ERC20) |
| Linea | 可用 | ETH、USDC (ERC20) |
| zkSync Era | 可用 | ETH、USDC (ERC20) |
| Scroll | 可用 | ETH、USDT (ERC20) |
| Aptos | 可用 | APT、USDT (fungible asset) |
| Sui | 可用 | SUI、USDC (coin objects) |
| TON | 可用 | GRAM、USDT (jetton) |

Polygon 也用同一個幣種編號，所以同一句助記詞在三條 EVM 鏈上是**同一個位址**。
它有兩件自己的事。它的幣叫 **POL**，2024 年 9 月從 MATIC 改名 —— 這一點是鏈自己說的，
也是這個錢包判斷的依據：包裝後的原生代幣合約報的是 `WPOL`。它的 USDT 合約自稱
**`USDT0`**，因為 Tether 把 Polygon 上的供應遷到了全鏈版本。它就是大家說的那個 USDT，
錢包也照 USDT 顯示；簽章前拿去跟鏈核對的，是合約實際叫什麼。Polygon 的歷史紀錄走
**Blockscout**，因為 NodeReal 不索引這條鏈。它不需要金鑰，所以是這裡唯一一個不用你
開口就會去聯繫的索引服務 —— 跟比特幣那邊用 Esplora 是同一筆交易，理由也一樣：
`eth_getLogs` 一次上限一萬個區塊，而 Polygon 1.5 秒一個塊，那只有四個小時，
何況原生轉帳根本不產生日誌。

設定裡的 **Etherscan API 金鑰**是可選的，一把就夠這裡所有 EVM 鏈用；填了就優先用它。

Base 是第四條 EVM 鏈，位址還是同一個。它的幣是 ETH —— 跟 Ethereum 是同一種資產，
兩條鏈上的轉帳只靠 chain id 區分。它做不到的是給這個幣定價：它自己的 Uniswap V2
WETH/USDT 池子確實存在，但**總共只有十七美元**，去問它一個 ETH 值多少，答案是十七。
Base 的流動性在 Aerodrome 和 Uniswap V3 上，這兩個都不是同一套介面，所以價格改從
Ethereum 的池子讀 —— 同一種資產，而且那條鏈本來就在聯繫。這跟 BTC 的做法是一樣的。
歷史紀錄跟 Polygon 一樣走 Blockscout。

還有一件事 Base 只跟 Optimism 共有：**手續費不等於 gas × 單價**。OP-stack rollup 會把
交易寫到 Ethereum 上，這筆錢由發送方在 L2 gas 之外另付，而且 `op-geth` 把它算進餘額
檢查裡 —— 所以一個把手續費當成 gas × 單價的錢包會正好差這麼多，「全部轉出」會被節點以
`have … want …` 拒掉。這個金額是拿真正要簽章的那串位元組去問鏈上的 L1 gas 價格預言機
取的，在確認頁單列一行。它不退。

鏈上按**壓縮後**的體積收費，所以「簽章還沒產生、拿什麼位元組佔位」不是細節而是錢：一串
重複的填充會被壓沒，預留就不夠。拿兩條鏈的預言機實測，這個缺口在 1.33 億到 6.33 億 wei
之間，取決於是哪條鏈、轉的是不是代幣。

Base 也是這裡唯一一條穩定幣是 **USDC 而不是 USDT** 的鏈。這不是偏好：Tether 在 Base
上的合約總共 2380 萬，Circle 的 USDC 是 42 億；幣安列出的 USDT 可提網路有 19 個，
裡面沒有 Base —— 它在 Base 上只支援 ETH 和 USDC。放一行 USDT 在那兒，是一行誰也填
不滿的餘額。所以「每條鏈一格代幣」現在是「這條鏈的穩定幣」，是哪個就寫哪個。

Arbitrum One 是第五條 EVM 鏈、第二條 rollup，而它收 L1 費用的方式正好相反：Nitro 把
寫到 Ethereum 的成本摺進了 gas **估算**裡 —— 一筆普通轉帳估出來是 21,302 而不是
21,000 —— 所以 `gas_limit × 單價` 已經包含了它，不需要另外預留。Base 需要那筆預留，
這條鏈必須沒有；在這裡憑空扣一筆，每次「全部轉出」都會剩下灰塵。它的幣也是 ETH，
價格同樣從 Ethereum 讀，理由跟 Base 一樣：它自己的池子只有大約三萬美元，報價慢了 14%。
它的 USDT 是真的 —— 8.35 億，幣安也能提過去 —— 只是合約自稱 `USD₮0`，那個 T 的位置
是圖格里克符號。這個名字只拿去跟鏈核對，從不顯示。

Optimism 是第六條 EVM 鏈、第三條 rollup，也是「是不是 rollup」這個問題失效的地方。它跟
Base 一樣是 OP-stack，所以要另外預留 L1 費用、要去問預言機；Arbitrum 同樣是 rollup，
卻絕不能問。想知道是哪一類，問鏈就行：一筆普通轉帳在兩條 OP-stack 鏈上都正好估 21,000
gas，在 Arbitrum 上估 21,422 —— 那個多出來的部分就是已經摺進去的寫入成本。

這條鏈上有兩樣東西照抄鄰居就是錯的。它的 Uniswap V2 路由位址跟 Base、Arbitrum **不一樣**
—— 那兩條鏈共用一個位址，而那個位址在 Optimism 上沒有程式碼，抄過來不會報錯，只會什麼都
不回傳，然後價格就悄悄沒了。另外，不像 Polygon 的 `USDT0` 和 Arbitrum 的 `USD₮0`，它的
USDT 合約老老實實就叫 `USDT`：2.235 億，位址跟幣安自己列的提幣位址一致。它的幣是 ETH，
價格從 Ethereum 讀，因為它自己的兩個 V2 池子分別只有十五美元和五百多美元，報出來的
ETH 價是 7.55 和 264。歷史紀錄走 Blockscout，只是這家開在自己的網域上。NodeReal 有這條
鏈的 RPC，但沒有對應的索引，所以歷史不走它。

這一批六條鏈一起加進來，分類的依據不是它們叫什麼，而是它們怎麼收 L1 的钱：

| 链 | 币 | 穩定幣 | L1 费用 | 幣價來源 |
|---|---|---|---|---|
| Avalanche | AVAX | USDT（`USDt`） | — | 自己的池子 |
| HyperEVM | HYPE | USDT（`USD₮0`） | — | **沒有** |
| Mantle | MNT | USDC | 在 gas 之外另收 | **沒有** |
| Linea | ETH | USDC | — | Ethereum |
| zkSync Era | ETH | USDC | 摺進 gas 裡 | Ethereum |
| Scroll | ETH | USDT | 另收，**而且位址不一樣** | Ethereum |

**Scroll 收 L1 用的是它自己的位址。** 它的 `L1GasPriceOracle` 在 `0x53..02`，
3,782 位元組；Base、Optimism、Mantle 共用的 OP-stack 預部署在 `0x42..0F`，2,055 位元組。
兩者認同一個 `getL1Fee(bytes)`，所以一個欄位能涵蓋兩種設計——但如果去 OP-stack 那個
位址上找 Scroll 的，會找到一片空白，然後一分錢都不預留。

**zkSync Era 一筆普通轉帳估出來是十七萬八千 gas**，不是 21,000。它跟 Arbitrum 一樣把
寫到 Ethereum 的成本摺進了 gas，只是摺得更徹底。它不另外收費。一個「覺得這數不對、
把它改回 21,000」的錢包，造出來的交易根本進不了塊。

**有兩條鏈故意不顯示幣價。** HYPE 和 MNT 在這個錢包接觸的其它鏈上都不存在，而它們
自己的 Uniswap V2 池子只有大約 1,100 美元和 400 美元。這麼小的池子不會報錯——它會
給你一個數。HyperEVM 那個池子的現價其實準到 0.1% 以内，但問它"一個幣值多少"，
答案低了 13%，因為一個幣就是池子的六分之一。所以估值那一列直說"不知道」，這是真話；
總比給一個錯得看不出來的數強。

**Avalanche 和 Mantle 的歷史紀錄走 Routescan**，就是跑 Snowtrace 的那家，不需要金鑰。
這兩條是它在這裡唯一支援的鏈——對另外十條它都回 `chain not supported`——而這也是這兩條鏈
唯一的索引來源：NodeReal 兩條都不涵蓋，也都沒有 Blockscout 實例。**Linea 的 Blockscout 開在一個它自己的瀏覽器都不寫出來的位址上**——`explorer.linea.build`
是個前端，對所有 API 路徑都回傳 HTML，真正的後端在 `api-explorer.linea.build`。
這樣一來只剩 **HyperEVM** 一條鏈的歷史紀錄需要你自己的 Etherscan key：它的 Blockscout
原本是 Hyperscan，現在已經跳轉到一個宣傳頁了。它會直說，不會裝作出錯。

**Avalanche 的名字裡帶著網路**——`Avalanche (AVAX C-Chain)`——因為它其實是三條鏈，
而位址本身說不清是哪一條。交易所三條都提供，其中兩條接受 `0x` 位址：C-Chain（就是這條），
還有 BNB Chain——它照單全收同樣的二十個位元組，然後把幣送到這個錢包的 Avalanche 頁面
永遠不會去看的地方。X-Chain 會當場拒絕這個位址，是三者裡唯一自己會攔的。

**同樣三個字母，四種寫法。** Tether 的合約在 Ethereum 和 Scroll 上自稱 `USDT`，
在 Polygon 上是 `USDT0`，在 Arbitrum 和 HyperEVM 上是帶圖格里克符號的 `USD₮0`，
在 Avalanche 上是小寫 t 的 `USDt`。每一個都會在簽名前跟鏈核對，而且一個都不會顯示到
螢幕上。

這裡有兩條鏈既不是 EVM，彼此也完全不一樣。

**Aptos** 把 coin 和 *fungible asset* 分成兩套東西，而它的 USDT 屬於後者。兩者的入口
函式不同、查餘額的方法也不同，拿一套去操作另一套不會轉錯金額——交易直接 abort。它的
位址是 `sha3_256(公钥 || scheme)`，所以同一把鑰匙換個簽章方案就是另一個帳戶。

交易編碼不是照著文件寫的，是跟鏈自己的編碼器對過的：Aptos 提供
`/transactions/encode_submission`，把交易交給它、它回傳簽章要涵蓋的位元組。這個錢包
產生的位元組跟它**逐位元組相同**，兩種轉帳分別 197 和 297 位元組。這件事很要緊，因為 BCS
不帶型別——長度位元組放錯位置不會得到一個損壞的交易，而是得到另一個交易，並且被正確
地簽了名。

它的手續費顯示的是**上限**而不是估算。Aptos 可以精確計價，但前提是拿到發送方的公鑰；
報價的時候這個錢包沒有——金鑰要到最後一步才推導，而位址是公鑰的雜湊、反推不回去。
沒用掉的 gas 不收費。

**Sui 上沒有「帳戶裡有個數字」這回事。** 幣是**物件**，每個都有 id、版本和摘要；餘額是
它們的和，轉帳花掉的是其中某幾個。這讓它成為繼 Bitcoin 之後第二條"發送是一次挑選而
不是一次減法"的鏈，也讓「版本過期」變成拒絕而不是少轉一點。它也沒有「轉帳」這條指令：
每筆交易都是一串命令，一次付款是先切一刀、再遞過去。

它的位址是 `blake2b256(scheme || 公鑰)`——注意順序，跟 Aptos 正好相反。兩條鏈、兩把
Ed25519 鑰匙、兩個 32 位元組位址，把兩個運算元調換一下，得到的是一個看起來完全正常、
卻沒有人握有私鑰的帳戶。驗證方法是從主網拿真實交易，從簽章裡讀出簽章者的公鑰，再重新
算一遍位址。

手續費來自對這筆交易本身的 dry run，這同時也證明了位元組是對的：鏈自己的解析器必須
讀懂它才能給它定價。有一個後果值得知道——Sui 會退還它收取的一部分儲存費，而把幣物件
合併起來正好釋放儲存，所以一筆把三十個物件摺在一起的轉帳**可能一分錢都不花**。

一個提醒：Sui 官方的公共全節點已經**停用**了 JSON-RPC，對所有方法都回
"Method not found"。這裡預設用的是另一個還在提供它的節點。

TON 在這裡是唯一一條**位址不是從金鑰算出來的**鏈。TON 上的錢包本身就是一個智慧合約，
位址是這個合約初始程式碼和儲存的雜湊。由此帶來的兩件事都擺在介面上，而不是等你自己撞上：
錢包轉出的第一筆要把合約程式碼一起帶出去，因為在那之前這個位址只是有餘額、卻沒有任何
能動它的東西；轉 USDT 需要 GRAM，因為代幣轉帳是兩個合約之間發訊息，每一跳都得靠隨
訊息帶上的錢才跑得動 —— 其中大部分會退回來。轉帳介面把這筆隨帶金額和手續費分開顯示，
而不是加在一起。

因為位址取決於錢包合約，**同一句助記詞，這裡的 TON 位址不一定和 Tonkeeper 或 Telegram
裡的一致** —— 除非它們也用 v4R2 和標準的 subwallet id，這是常見預設值，但不是保證。
幣叫 GRAM：2026 年 6 月 15 日從 Toncoin 改回了它在 Telegram 2018 年白皮書裡的名字。
改的只是代號 —— 網路還是 TON，位址和餘額都沒變。

鏈相關的程式碼只集中在一個 crate 裡。金鑰推導、儲存、加密和介面都是共用且與鏈無關的，
資料庫從第一版遷移起就帶著一張有 SLIP-44 幣種編號的 `chains` 表。
本文裡關於能量、頻寬和手續費估算的部分是 TRON 特有的；其餘內容適用於任何鏈。

## 你的錢包就是一個檔案

這一節值得看懂，因為備份和換機器全靠它。

```
neko-wallet.db     ← 這就是錢包。全部。
```

一個檔案。沒有 `-wal`、沒有 `-shm`、沒有任何附屬狀態 —— 資料庫跑在
`journal_mode = DELETE` 下就是為了這個：拷貝這個檔案等於拷貝了全部。
它整體加密，所以可以放在那些你絕不會放私鑰的地方：

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/            # 隨身碟
cp ~/.local/bin/neko-wallet.db ~/Dropbox/backup/        # 雲端硬碟
```

要使用別處的金庫：

```bash
neko-wallet set db /Volumes/USB/neko-wallet.db   # 從此記住
neko-wallet --db /Volumes/USB/neko-wallet.db     # 只這一次
neko-wallet --where-db                           # 現在開啟的是哪個？
neko-wallet unset db                             # 恢復預設搜尋
```

`set db` 不需要信箱和密碼：它只記一個路徑，別的什麼都不做。
路徑不存在時它會拒絕，除非你加 `--new` —— 因為路徑不存在通常就是打錯了，
而後果是一個看起來像「我的錢包不見了」的首次設定畫面。

開啟哪個檔案的順序：`--db` → `$NEKO_WALLET_DB` → 儲存的設定 →
執行檔同目錄 → 系統資料目錄。

## 備份

有兩種備份，而它們的失效方式**正好相反**。在你真正需要它們之前，值得先搞清楚誰是誰。

### `.db` 檔案 —— 該依靠的是這個

整體加密。放在隨身碟或雲端硬碟上的副本就是一坨密文：撿到的人依然需要你的信箱和密碼。
所以儘管多拷、經常拷。

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/
```

它擋不住的是**你自己忘記密碼**。到那一步，這個檔案對你的用處和對小偷的用處完全一樣：沒有。

### 助記詞 —— 最後的退路，不是日常備份

> [!CAUTION]
> **不建議把這十二個詞抄在紙上當作主要備份。**
> 紙上的助記詞是**明文的持有型憑證**：任何人只要讀到它，就能立刻把你的錢轉走 ——
> 闖空門的小偷、來家裡的客人、從你肩後拍的一張照片，或者乾脆直接從你手裡搶走。
> 它不會問密碼，也不會有任何提示。`.db` 檔案完全沒有這個性質，
> 這正是它才是該依靠的那份備份的原因。

如果你確實要抄下來，那張紙就等價於錢包裡的錢，也該用同樣的方式保管：

- 保險箱或銀行保管箱。不是抽屜，不是筆記本，不是書頁之間。
- **絕對不要**拍照、存進雲端筆記、傳給自己、或者輸入任何裝置。
  只要會同步，它就已經脫離你的控制了。
- 金額值得的話，拆成兩份分開存放，讓一次闖空門不足以拿走全部。

唯一能讓「助記詞被偷走也沒用」的東西是 BIP39 passphrase —— 一個只存在你腦子裡的
「第 25 個詞」。neko-wallet 在**匯入**錢包時支援它，但產生新錢包時還沒有提供設定入口。

## 轉帳

確認方式不是按一個鍵，而是**手動輸入收款地址的最後 6 個字元**。

```
   收款  TPZrDZ TUWQqqUTVRxAmSdQyGXSSg AUyyk4
         ^^^^^^                        ^^^^^^

   請輸入最後 6 個字元以確認：
         [ AUyyk_ ]  5/6
```

剪貼簿劫持惡意軟體在你貼上時替換收款地址，是命令列錢包最主要的真實損失來源。
按 `y` 擋不住它 —— 因為你看的是你**以為**自己貼上的東西。
手動輸入末尾幾位是唯一強迫你的眼睛落到即將被簽章的那串位元組上的動作。

然後要再輸入一次完整密碼。一個人走開了、還開著的終端機，不該足以把錢轉走。

**手續費會拆開顯示**，因為 TRON 沒有固定手續費：轉帳消耗頻寬，合約呼叫消耗能量，
只有你的帳戶涵蓋不了的那部分才會燒 TRX。能量是針對你這一筆交易向鏈上模擬出來的，
從不靠猜 —— 同樣一筆 USDT，轉給從沒持有過 USDT 的地址大約要貴一倍。

### 地址投毒

攻擊者會從一個長得很像你常用地址的地方給你轉粉塵，等你從交易紀錄裡複製錯。
三重防禦：

- 粉塵交易預設隱藏。
- **任何地址都不縮寫顯示。** 一旦渲染成 `TPZr…yyk4`，冒牌貨和真貨就沒法區分了。
- 收款地址如果**像但不等於**你交易紀錄裡的某個地址，會明確警告。

## 助記詞

按 `m` 檢視某個錢包的十二個詞。在那之前：

- 即使金庫已經解鎖，也會**完整重跑一遍** Argon2id 驗證你的密碼。
- 詞是遮住的，方向鍵**一次只揭開一個**。截圖或 `tmux capture-pane`
  漏掉的是十二分之一，不是全部。
- 60 秒後自動隱藏。
- **複製不是「被拒絕」，而是根本不存在。** 那個畫面到任何剪貼簿後端之間沒有程式路徑，
  所以不存在一個將來可能被 bug 反轉的判斷。

畫面上也會寫清楚這些都擋不住什麼：相機、背後的人、`script`、螢幕錄影軟體，
以及已經在你機器上的木馬。一個聲稱終端機能守住螢幕上的祕密的錢包，是在說謊。

在你把這些詞抄到紙上之前，請先讀[備份](#備份) —— 抄下來的助記詞是持有型憑證，
`.db` 檔案才是更安全的那份備份。

## 它是怎麼運作的

### 金鑰階層

```
信箱+密碼 ─Argon2id─► stretched ─HKDF─┬─► 檔案金鑰 ──► SQLCipher（整個資料庫）
                                      └─► KEK ──► 解封 MK（32 位元組隨機）
                                                   │
                                              HKDF ├─► k_data   欄位級 AEAD
                                                   └─► k_index  盲索引
```

每個錢包各有一份獨立的 BIP39 助記詞，用 `k_data` 加密後存入資料庫。
`MK` 是純隨機的、與任何助記詞無關 —— 這正是為什麼**沒有主助記詞**。
改密碼只需重新封裝那 32 位元組，不用重新加密任何業務資料，而且是當機安全的
（切換完成前兩份封裝都保留）。

### 兩層加密

整個檔案由 SQLCipher 加密（AES-256-CBC + HMAC-SHA512）。在這之上，
那些一旦外洩就等於丟錢的東西還各自套了一層獨立金鑰的 XChaCha20-Poly1305：

| 欄位 | 第二層 |
|---|---|
| 助記詞熵 | 有 |
| 私鑰 | 有 |
| 錢包名稱 | 有 —— 「公司備用金」本身就是情報 |
| TronGrid API Key | 有 |
| 地址、交易、餘額 | 無 —— 鏈上本就公開，且需要索引排序 |

每段密文的 AAD 都綁定了表名、欄位名、列 ID 和金鑰版本，所以密文列之間無法掉包。

### 鹽存在哪

一個自我包含的檔案必須只靠它自己就能解密，但你得**先拿到鹽**才能解密。
SQLCipher 把它那 16 位元組的鹽放在檔案最前面、以明文儲存 —— 所以我們把那個位置
當成自己的檔案標頭用：格式版本、KDF 檔位，加 14 位元組本金庫唯一的隨機數。

把檔位放在未認證的標頭裡是安全的：改了它就會算出不一樣的金鑰，檔案直接開不了。
降級攻擊自己把自己廢掉了。

### 計算成本

Argon2id，安裝時在你的機器上實測校準 —— 128 MiB / t=4、256 MiB / t=3
或 1 GiB / t=4。檔位編號寫在標頭裡，所以在快機器上建立的金庫拿到慢機器照樣能開。

密碼必須通過 70 bit 的估算熵，取「字元集法」和「模式法」兩者中**較小**的那個，
所以 `MyWallet2026!` 會被算成它實際的樣子。

### 交易在本機組裝

絕不呼叫 `/wallet/createtransaction`。節點只提供區塊參照；
即將被簽章的位元組由本機用手寫的 protobuf 編碼器組裝，簽完立刻從簽章還原公鑰、
斷言地址一致。一個惡意節點沒法塞給你一筆轉給他自己的交易再騙你簽字。

## 升級

再跑一次安裝腳本。

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

它替換執行檔，絕不碰你的 `.db` —— 結束時會明確告訴你這一點。

**這裡故意不做自動更新。** 一個能替換自己執行檔的錢包，就等於在保管私鑰的機器上
開了一條遠端程式碼通道，再多的簽章驗證也不會讓這條通道比「根本沒有」更小。
CI 會強制這一點：相依樹裡一旦重新出現自我替換相關的 crate，
或者程式多出白名單以外的連網目標，建置就會失敗。
白名單必須手動修改才能擴大，目前只有：三條鏈的節點、可選的 BNB Chain 歷史索引服務，
以及瀏覽器連結（只複製給你，錢包自己從不存取）。

## 擋得住什麼，擋不住什麼

**擋得住：**

- `.db` 檔案被拷走、同步到雲端外洩、或從丟棄的硬碟裡被復原 —— 沒有密碼它就是密文。
- 對密文逐列逐欄的竄改。
- 竄改 KDF 成本參數讓檔案變得更容易破解。
- 惡意或被攻破的節點，試圖騙你簽一筆轉給別人的交易。

**擋不住：**

- **忘記密碼。** 永久、徹底遺失。這就是「零恢復」的含義。
- 你執行它的機器上的鍵盤側錄或遠端控制木馬。**它不是硬體錢包**：
  金庫開啟期間，私鑰就在這台電腦的記憶體裡，終端機程式改變不了這一點。
- 對已解鎖行程的記憶體傾印。金鑰會做歸零處理、盡量不放進 `String`，但作業系統層面擋不住。
- 有人從你螢幕上讀走助記詞。
- 弱密碼。`Password123` 配上 Argon2id，它依然是 `Password123`。

## 開發

```bash
cargo test --workspace                              # 275 個測試
cargo clippy --workspace --all-targets -- -D warnings
```

密碼學、金鑰推導和 TRON 交易編碼都對照 `vectors/` 裡凍結的跨語言測試向量檢查 ——
逐位元組比對，所以任何改動只要讓推導出的地址或交易 ID 變了，立刻就會失敗。

```
neko-crypto   Argon2id / XChaCha20-Poly1305 / HKDF。無 IO、無 SQL、無 async
neko-vault    金鑰階層、KDF 檔位、密碼政策、正規化
neko-store    SQLCipher、遷移、欄位級信封（永不推導金鑰）
neko-hd       BIP39 / BIP32 / BIP44 與 SLIP-0010；TRON、EVM、Solana 地址編解碼
neko-tron     僅 TRON：protobuf、交易組裝與簽章、節點用戶端
neko-evm      五條 EVM 鏈：RLP、EIP-155/1559 簽章、ABI、JSON-RPC、rollup 手續費
neko-solana   Solana：Ed25519、交易編碼、代幣帳戶、叢集 RPC
neko-btc      Bitcoin：bech32、隔離見證簽章、選幣、Esplora
neko-ton      TON：cell 與 BoC、錢包合約 v4R2、jetton、toncenter
neko-core     介面唯一對話的門面
neko-i18n     編譯期檢查的翻譯表
neko-tui      ratatui 介面
```
