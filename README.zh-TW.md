# Neko Wallet

---

一個跑在終端機裡的自託管加密錢包。整個錢包就是**一個加密檔案** ——
插隨身碟帶走、放雲端硬碟、隨便拷到哪裡都行。用一個信箱加一個密碼解鎖，
而這兩樣東西哪裡都沒有儲存。

多鏈架構；TRON 已可用。

## 這東西是做什麼的

一個在終端機裡執行的加密貨幣錢包。私鑰存在本機加密的 SQLite 金庫裡；沒有帳號要登入，
沒有伺服器保存任何東西，也不做同步。程式會聯繫的只有**你自己指定的鏈節點**，
以及 —— 僅當你自己填了 Key 時 —— 一個用於 BNB Chain 歷史的索引服務。
不檢查更新、不回報資料、沒有任何統計，**也沒有行情服務**：錢包列表裡那個估值
是從鏈上的兌換池直接問出來的，所以顯示它不花費任何隱私。它以 USDT 計價而不是美元，
並且介面上如實標註 —— 因為那才是實際問到的東西。

從儲存結構往上就是照著**錢包 → 鏈 → 資產**設計的。目前能用的是 TRON，
見[支援的鏈](#支援的鏈)。

金庫是**一個自我包含的檔案**。拷到隨身碟上，回頭再放回來，東西全在。
別人把這個檔案拿走，拿到的是一堆密文。

```
$ neko-wallet
信箱: zoe@example.com
密碼:

  ⠸ 正在推導金鑰... 這裡慢是故意的

┌──────────────────────── 錢包 ────────────────────────┐
│ > 儲蓄            TPZrDZ...  8.655007 TRX  7.00 USDT  │
│   日常            TWx3kQ...  0.000000 TRX  0.00 USDT  │
└───────────────────────────────────────────────────────┘
 n 新增   i 匯入   Enter 開啟   s 設定   q 離開
```

> [!WARNING]
> **沒有任何找回途徑。** 沒有主助記詞、沒有重設連結、沒有客服。
> 忘了信箱或密碼，錢包就沒了 —— 你的處境和拿走檔案的小偷完全一樣。
> 這是設計，不是缺陷。請給 `.db` 留一份副本 —— 它是加密的，所以複製既便宜又安全。
> 在你考慮把助記詞抄在紙上之前，請先讀[備份](#備份)：那一步沒有聽起來那麼無害。

## 安裝

**macOS、Linux、WSL：**

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

**Windows PowerShell：**

```powershell
irm https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.ps1 | iex
```

**Windows CMD：**

```
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.cmd -o install.cmd && install.cmd
```

安裝腳本下載適合你機器的版本，對照公布的校驗碼驗證，放進 PATH，然後就結束了。
它不建立錢包，也不跟你要任何東西。

把腳本管線給 shell 意味著執行那個 URL 提供的任何東西，介意的話請先讀一遍 ——
[install.sh](install.sh) 大約兩百行。`NEKO_WALLET_INSTALL_DIR` 改安裝位置，
`NEKO_WALLET_NO_PATH=1` 則不動你的 shell 啟動檔。

### 從原始碼編譯

```bash
cargo install --git https://github.com/zoefix/neko-wallet
```

單一執行檔，沒有執行期相依 —— SQLCipher 是編譯進去的。Windows 上從原始碼編譯需要
Perl 和 NASM，因為那邊的 OpenSSL 要從原始碼建置。

## 上手

```bash
neko-wallet
```

首次執行會讓你設定信箱和密碼，並建立金庫。然後：

| 按鍵 | 作用 |
|---|---|
| `n` | 新增錢包（產生助記詞，但**不顯示**） |
| `i` | 從助記詞或私鑰匯入 |
| `Enter` | 開啟 → 鏈 → 資產 |
| `y` | 複製地址 |
| `s` | 轉帳 |
| `t` | 交易紀錄 |
| `m` | 檢視這個錢包的助記詞 |
| `<` `>` | 切換語言 |
| `L` | 立即鎖定 |

新增錢包時不會給你看助記詞。你要在之後主動按 `m` 去看 —— 而那會再問一次密碼。

## 支援的鏈

一個錢包的那一份助記詞，涵蓋它底下的所有鏈 —— BIP44 推導路徑就是做這個用的。
加一條鏈，永遠不代表新錢包、新助記詞、或者多一樣要備份的東西。

| 鏈 | 狀態 | 資產 |
|---|---|---|
| TRON | 可用 | TRX、USDT (TRC20) |
| Bitcoin | 介面裡已列出，功能還沒做 | — |

鏈相關的程式碼只集中在一個 crate 裡。金鑰推導、儲存、加密和介面都是共用且與鏈無關的，
資料庫從第一版遷移起就帶著一張有 SLIP-44 幣種編號的 `chains` 表。
本文裡關於能量、頻寬和手續費估算的部分是 TRON 特有的；其餘內容適用於任何鏈。

## 你的錢包就是一個檔案

這一節值得看懂，因為備份和換機器全靠它。

```
neko-wallet.db     ← 這就是錢包。全部。
```

一個檔案。沒有 `-wal`、沒有 `-shm`、沒有任何附屬狀態 —— 資料庫跑在
`journal_mode = DELETE` 下就是為了這個：拷貝這個檔案等於拷貝了全部。
它整體加密，所以可以放在那些你絕不會放私鑰的地方：

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/            # 隨身碟
cp ~/.local/bin/neko-wallet.db ~/Dropbox/backup/        # 雲端硬碟
```

要使用別處的金庫：

```bash
neko-wallet set db /Volumes/USB/neko-wallet.db   # 從此記住
neko-wallet --db /Volumes/USB/neko-wallet.db     # 只這一次
neko-wallet --where-db                           # 現在開啟的是哪個？
neko-wallet unset db                             # 恢復預設搜尋
```

`set db` 不需要信箱和密碼：它只記一個路徑，別的什麼都不做。
路徑不存在時它會拒絕，除非你加 `--new` —— 因為路徑不存在通常就是打錯了，
而後果是一個看起來像「我的錢包不見了」的首次設定畫面。

開啟哪個檔案的順序：`--db` → `$NEKO_WALLET_DB` → 儲存的設定 →
執行檔同目錄 → 系統資料目錄。

## 備份

有兩種備份，而它們的失效方式**正好相反**。在你真正需要它們之前，值得先搞清楚誰是誰。

### `.db` 檔案 —— 該依靠的是這個

整體加密。放在隨身碟或雲端硬碟上的副本就是一坨密文：撿到的人依然需要你的信箱和密碼。
所以儘管多拷、經常拷。

```bash
cp ~/.local/bin/neko-wallet.db /Volumes/USB/
```

它擋不住的是**你自己忘記密碼**。到那一步，這個檔案對你的用處和對小偷的用處完全一樣：沒有。

### 助記詞 —— 最後的退路，不是日常備份

> [!CAUTION]
> **不建議把這十二個詞抄在紙上當作主要備份。**
> 紙上的助記詞是**明文的持有型憑證**：任何人只要讀到它，就能立刻把你的錢轉走 ——
> 闖空門的小偷、來家裡的客人、從你肩後拍的一張照片，或者乾脆直接從你手裡搶走。
> 它不會問密碼，也不會有任何提示。`.db` 檔案完全沒有這個性質，
> 這正是它才是該依靠的那份備份的原因。

如果你確實要抄下來，那張紙就等價於錢包裡的錢，也該用同樣的方式保管：

- 保險箱或銀行保管箱。不是抽屜，不是筆記本，不是書頁之間。
- **絕對不要**拍照、存進雲端筆記、傳給自己、或者輸入任何裝置。
  只要會同步，它就已經脫離你的控制了。
- 金額值得的話，拆成兩份分開存放，讓一次闖空門不足以拿走全部。

唯一能讓「助記詞被偷走也沒用」的東西是 BIP39 passphrase —— 一個只存在你腦子裡的
「第 25 個詞」。neko-wallet 在**匯入**錢包時支援它，但產生新錢包時還沒有提供設定入口。

## 轉帳

確認方式不是按一個鍵，而是**手動輸入收款地址的最後 6 個字元**。

```
   收款  TPZrDZ TUWQqqUTVRxAmSdQyGXSSg AUyyk4
         ^^^^^^                        ^^^^^^

   請輸入最後 6 個字元以確認：
         [ AUyyk_ ]  5/6
```

剪貼簿劫持惡意軟體在你貼上時替換收款地址，是命令列錢包最主要的真實損失來源。
按 `y` 擋不住它 —— 因為你看的是你**以為**自己貼上的東西。
手動輸入末尾幾位是唯一強迫你的眼睛落到即將被簽章的那串位元組上的動作。

然後要再輸入一次完整密碼。一個人走開了、還開著的終端機，不該足以把錢轉走。

**手續費會拆開顯示**，因為 TRON 沒有固定手續費：轉帳消耗頻寬，合約呼叫消耗能量，
只有你的帳戶涵蓋不了的那部分才會燒 TRX。能量是針對你這一筆交易向鏈上模擬出來的，
從不靠猜 —— 同樣一筆 USDT，轉給從沒持有過 USDT 的地址大約要貴一倍。

### 地址投毒

攻擊者會從一個長得很像你常用地址的地方給你轉粉塵，等你從交易紀錄裡複製錯。
三重防禦：

- 粉塵交易預設隱藏。
- **任何地址都不縮寫顯示。** 一旦渲染成 `TPZr…yyk4`，冒牌貨和真貨就沒法區分了。
- 收款地址如果**像但不等於**你交易紀錄裡的某個地址，會明確警告。

## 助記詞

按 `m` 檢視某個錢包的十二個詞。在那之前：

- 即使金庫已經解鎖，也會**完整重跑一遍** Argon2id 驗證你的密碼。
- 詞是遮住的，方向鍵**一次只揭開一個**。截圖或 `tmux capture-pane`
  漏掉的是十二分之一，不是全部。
- 60 秒後自動隱藏。
- **複製不是「被拒絕」，而是根本不存在。** 那個畫面到任何剪貼簿後端之間沒有程式路徑，
  所以不存在一個將來可能被 bug 反轉的判斷。

畫面上也會寫清楚這些都擋不住什麼：相機、背後的人、`script`、螢幕錄影軟體，
以及已經在你機器上的木馬。一個聲稱終端機能守住螢幕上的祕密的錢包，是在說謊。

在你把這些詞抄到紙上之前，請先讀[備份](#備份) —— 抄下來的助記詞是持有型憑證，
`.db` 檔案才是更安全的那份備份。

## 語言

English、简体中文、繁體中文、日本語。依系統語言自動偵測，隨時用設定裡的
`<` `>` 切換，並依金庫記住。

每種語言都用它自己的文字列出，這樣看不懂目前語言的人也能找到出路。
翻譯在編譯期檢查：缺 key、`%{佔位符}` 對不上、或出現歧義寬度字元，
都會讓建置失敗，而不是流到一個正拿著錢的使用者面前。

## 它是怎麼運作的

### 金鑰階層

```
信箱+密碼 ─Argon2id─► stretched ─HKDF─┬─► 檔案金鑰 ──► SQLCipher（整個資料庫）
                                      └─► KEK ──► 解封 MK（32 位元組隨機）
                                                   │
                                              HKDF ├─► k_data   欄位級 AEAD
                                                   └─► k_index  盲索引
```

每個錢包各有一份獨立的 BIP39 助記詞，用 `k_data` 加密後存入資料庫。
`MK` 是純隨機的、與任何助記詞無關 —— 這正是為什麼**沒有主助記詞**。
改密碼只需重新封裝那 32 位元組，不用重新加密任何業務資料，而且是當機安全的
（切換完成前兩份封裝都保留）。

### 兩層加密

整個檔案由 SQLCipher 加密（AES-256-CBC + HMAC-SHA512）。在這之上，
那些一旦外洩就等於丟錢的東西還各自套了一層獨立金鑰的 XChaCha20-Poly1305：

| 欄位 | 第二層 |
|---|---|
| 助記詞熵 | 有 |
| 私鑰 | 有 |
| 錢包名稱 | 有 —— 「公司備用金」本身就是情報 |
| TronGrid API Key | 有 |
| 地址、交易、餘額 | 無 —— 鏈上本就公開，且需要索引排序 |

每段密文的 AAD 都綁定了表名、欄位名、列 ID 和金鑰版本，所以密文列之間無法掉包。

### 鹽存在哪

一個自我包含的檔案必須只靠它自己就能解密，但你得**先拿到鹽**才能解密。
SQLCipher 把它那 16 位元組的鹽放在檔案最前面、以明文儲存 —— 所以我們把那個位置
當成自己的檔案標頭用：格式版本、KDF 檔位，加 14 位元組本金庫唯一的隨機數。

把檔位放在未認證的標頭裡是安全的：改了它就會算出不一樣的金鑰，檔案直接開不了。
降級攻擊自己把自己廢掉了。

### 計算成本

Argon2id，安裝時在你的機器上實測校準 —— 128 MiB / t=4、256 MiB / t=3
或 1 GiB / t=4。檔位編號寫在標頭裡，所以在快機器上建立的金庫拿到慢機器照樣能開。

密碼必須通過 70 bit 的估算熵，取「字元集法」和「模式法」兩者中**較小**的那個，
所以 `MyWallet2026!` 會被算成它實際的樣子。

### 交易在本機組裝

絕不呼叫 `/wallet/createtransaction`。節點只提供區塊參照；
即將被簽章的位元組由本機用手寫的 protobuf 編碼器組裝，簽完立刻從簽章還原公鑰、
斷言地址一致。一個惡意節點沒法塞給你一筆轉給他自己的交易再騙你簽字。

## 升級

再跑一次安裝腳本。

```bash
curl -fsSL https://raw.githubusercontent.com/zoefix/neko-wallet/main/install.sh | sh
```

它替換執行檔，絕不碰你的 `.db` —— 結束時會明確告訴你這一點。

**這裡故意不做自動更新。** 一個能替換自己執行檔的錢包，就等於在保管私鑰的機器上
開了一條遠端程式碼通道，再多的簽章驗證也不會讓這條通道比「根本沒有」更小。
CI 會強制這一點：相依樹裡一旦重新出現自我替換相關的 crate，
或者程式多出 TRON 節點以外的連網目標，建置就會失敗。

## 擋得住什麼，擋不住什麼

**擋得住：**

- `.db` 檔案被拷走、同步到雲端外洩、或從丟棄的硬碟裡被復原 —— 沒有密碼它就是密文。
- 對密文逐列逐欄的竄改。
- 竄改 KDF 成本參數讓檔案變得更容易破解。
- 惡意或被攻破的節點，試圖騙你簽一筆轉給別人的交易。

**擋不住：**

- **忘記密碼。** 永久、徹底遺失。這就是「零恢復」的含義。
- 你執行它的機器上的鍵盤側錄或遠端控制木馬。**它不是硬體錢包**：
  金庫開啟期間，私鑰就在這台電腦的記憶體裡，終端機程式改變不了這一點。
- 對已解鎖行程的記憶體傾印。金鑰會做歸零處理、盡量不放進 `String`，但作業系統層面擋不住。
- 有人從你螢幕上讀走助記詞。
- 弱密碼。`Password123` 配上 Argon2id，它依然是 `Password123`。

## 開發

```bash
cargo test --workspace                              # 275 個測試
cargo clippy --workspace --all-targets -- -D warnings
```

密碼學、金鑰推導和 TRON 交易編碼都對照 `vectors/` 裡凍結的跨語言測試向量檢查 ——
逐位元組比對，所以任何改動只要讓推導出的地址或交易 ID 變了，立刻就會失敗。

```
neko-crypto   Argon2id / XChaCha20-Poly1305 / HKDF。無 IO、無 SQL、無 async
neko-vault    金鑰階層、KDF 檔位、密碼政策、正規化
neko-store    SQLCipher、遷移、欄位級信封（永不推導金鑰）
neko-hd       BIP39 / BIP32 / BIP44、TRON 地址編解碼
neko-tron     僅 TRON：protobuf、交易組裝與簽章、節點用戶端
neko-core     介面唯一對話的門面
neko-i18n     編譯期檢查的翻譯表
neko-tui      ratatui 介面
```
